# TTS for the Assayer's voice — getting a band word and a 25-word quip spoken in the browser within about a second

Researched 2026-09-05 for the [design brief](../design-brief.md). Question: the Assayer (Gemini 3.8 Flash, returning JSON) grades a round and writes a ~25-word comedic quip. We want one band word ("close", "meld"…) plus that quip **spoken aloud on one device** — a laptop or an Android phone, in the browser — with audio **ready within roughly one second of the verdict landing**. The server is Elixir/Phoenix on a DigitalOcean VPS in New York and can call any HTTP API. Which text-to-speech route gets there, and is a native audio-out model a real alternative? Owner-held API keys are ignored.

Method: every claim traces to a primary source — vendor docs, API references, model cards, pricing pages, the Azure retail-prices API, and browser-vendor documentation (developer.chrome.com, webkit.org, MDN) — all fetched 2026-09-05. Secondary sources are labelled. Where an official page does not state a figure the cell says **not found**; nothing is estimated except the explicitly *computed* per-quip cost column, which is arithmetic on cited prices. No vendor is recommended; §5 states implications only. Model-latency figures for the Assayer's own verdict are covered in [model-selection-for-play.md](model-selection-for-play.md) and are not re-derived.

Working assumptions used only for arithmetic: a 25-word quip is ~150 characters and ~8–10 s of speech at ordinary pace (Azure's voice list reports ~150 words per minute for `en-US-JennyNeural` in its [REST reference](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)).

### 1d. Friction from plain HTTP in Elixir

- **Fine over plain HTTP + WebSocket** (a Req/Finch call or a Mint WebSocket): ElevenLabs, OpenAI, Gemini API, Cartesia (needs a dated `Cartesia-Version` header, e.g. `2026-08-14` — [bytes](https://docs.cartesia.ai/api-reference/tts/bytes)), Deepgram, Hume, Inworld, Rime, Fish, MiniMax, PlayHT.
- **Google Cloud TTS**: bidirectional streaming is shown only through client libraries and is "only compatible with Chirp 3: HD voices" ([streaming guide](https://docs.cloud.google.com/text-to-speech/docs/create-audio-text-streaming)); unary REST works. Google OAuth service-account tokens are needed rather than an API key.
- **Amazon Polly**: SigV4 signing; the bidirectional API rides "HTTP/2 headers" and event-stream frames ([StartSpeechSynthesisStream](https://docs.aws.amazon.com/polly/latest/dg/API_StartSpeechSynthesisStream.html)); raw PCM is capped at 16 kHz ([SynthesizeSpeech](https://docs.aws.amazon.com/polly/latest/dg/API_SynthesizeSpeech.html)); generative voices are regional (us-east-1 is listed) ([generative voices](https://docs.aws.amazon.com/polly/latest/dg/generative-voices.html)).
- **Azure**: regional endpoints `https://{region}.tts.speech.microsoft.com/cognitiveservices/v1`, an SSML body, and Microsoft's own warning that "Use cases for the text to speech REST API are limited. Use it only in cases where you can't use the Speech SDK" ([REST](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)); input-text streaming is SDK-only ([latency guide](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-lower-speech-synthesis-latency)).
- **Kokoro / Fish S2 Pro self-hosted**: you own the GPU, the process supervision and the latency; the VPS has no GPU.

## 2. Native audio-out models — can one call return the JSON verdict *and* the spoken quip?

**Gemini.** The models page lists `gemini-3.8-flash` with inputs "Text, Image, Video, Audio" and outputs **"Text, Image"** — no audio output via `generateContent` ([models](https://ai.google.dev/gemini-api/docs/models)). The models that do emit audio are the TTS models, which "can only receive text inputs and generate audio outputs" ([speech generation](https://ai.google.dev/gemini-api/docs/speech-generation)), and the Live API native-audio models (`gemini-3.1-flash-live-preview`, `gemini-2.5-flash-native-audio-preview-12-2025`), which run over a "Stateful WebSocket connection (WSS)" ([Live](https://ai.google.dev/gemini-api/docs/live)) and "only support `AUDIO` response modality" — text comes back only as an output-audio transcription ([Live capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities)). The structured-output guide says nothing about audio modalities ([structured output](https://ai.google.dev/gemini-api/docs/structured-output)). So on Gemini there is no single call that returns a JSON verdict and audio; the Assayer's grading call and the voice are necessarily two calls.

**OpenAI.** Chat Completions accepts `modalities: ["text", "audio"]` — "`["text"]` is the default" — with an `audio` object of voice and format `wav`, `aac`, `mp3`, `flac`, `opus` or `pcm16`; `response_format` `json_schema` exists on the same request and the reference states no restriction either way ([chat/create](https://developers.openai.com/api/docs/api-reference/chat/create)). The current audio model is `gpt-audio-1.5`: Chat Completions only, "Streaming" and "Function calling" supported, structured outputs **not listed** on its page; text $2.50 / $10.00, audio $32.00 / $64.00 per 1M tokens; latency not found ([gpt-audio-1.5](https://developers.openai.com/api/docs/models/gpt-audio-1.5)). Realtime (`gpt-realtime-2.1`, over WebRTC / WebSocket / SIP — [realtime](https://developers.openai.com/api/docs/guides/realtime)) can be configured so that "If both audio and text are enabled for the current session, the model will respond with both audio and text content", output `audio/pcm` at 24 kHz ([realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations)); audio output is $64.00 / 1M tokens, versus $12.00 for `gpt-4o-mini-tts` ([pricing](https://developers.openai.com/api/docs/pricing)). Whether JSON-schema enforcement applies to the text half of an audio response is **not documented**, so the "one call" exists only if the Assayer moves to an OpenAI audio model and the verdict schema is trusted to prompt discipline rather than the API.

## 3. Architecture comparison

**Text-then-TTS.** Verdict JSON returns (latency per [model-selection-for-play.md](model-selection-for-play.md)); the server immediately POSTs the quip to a TTS endpoint and relays or hands the browser a URL; the 2.5 s reveal beat runs in parallel. With the vendors' own numbers, first audio lands at model latency + two network legs: ~75 ms model / 100–150 ms regional TTFB (ElevenLabs Flash), 20–100 ms P90 server-side (Inworld), ~37 ms P50 (Rime Mist v3), sub-90 ms (Cartesia), ~100–300 ms (Hume), <300 ms (Azure HD), and ~277 ms TTFB after TLS or "approximately 600 ms" + ~60 ms for a whole 150-char clip unstreamed (Deepgram Aura-2). Every figure in §1a is under the 2.5 s beat even without streaming, and under 1 s for every vendor that publishes a number — the unknowns are OpenAI, Gemini, Google Cloud, Polly, PlayHT and MiniMax, which publish none. Cost is one TTS call per round: $0.002–$0.02 (§1c). The spoken line is byte-identical to the displayed quip because it is the same string.

**Native audio-out.** One request carries both modalities only at OpenAI (§2). It removes the second network round-trip but adds three costs: audio-token pricing at $64 / 1M output tokens; a change of Assayer model with no published judging quality for `gpt-audio-1.5`; and no documented guarantee that the audio says what the JSON says — a transcript arrives, but it is the model's rendition, not the verdict field. The wall-clock saving cannot be quantified here because neither OpenAI nor Google publishes a first-audio figure for these models.

**Caching.** The game caches verdicts, so a cache hit skips the Assayer entirely; the quip text is instant and TTS becomes the *only* remaining latency — which means the text-then-TTS path is the one that benefits from cache hits, while a native audio-out design would re-run the expensive grading call just to get a voice. If audio bytes are cached beside the verdict (a 150-char MP3 at 48 kbps is a few tens of kilobytes), replays are free and instant; if a fresh performance per replay is wanted, regeneration costs one TTS call and the §1a latencies. With the same text, tag-driven models (v3, Gemini-TTS, Inworld TTS-2, Azure Omni) vary delivery run to run — Azure exposes this directly as `temperature`, "Prosody variations … slight variations in each output" ([HD voices](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/high-definition-voices)).

## 4. Browser playback facts

Autoplay with sound is gated on a prior user gesture: Chrome allows it once "The user has interacted with the domain (click, tap, etc.)" (desktop also via the Media Engagement Index or an installed PWA), and "If an AudioContext is created before the document receives a user gesture, it will be created in the 'suspended' state" — call `resume()` inside a gesture ([Chrome autoplay policy](https://developer.chrome.com/blog/autoplay)); Safari says "Websites should assume any use of `<video>` or `<audio>` requires a user gesture click to play" and to check the `play()` promise ([WebKit](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)); MDN's guide adds that autoplay is permitted when muted, after interaction, or when allowlisted, and shows catching `NotAllowedError` ([MDN autoplay](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)). In our game the tap that submits the round is that gesture, so the verdict audio is allowed as long as the `AudioContext` or `<audio>` element is created or resumed in the tap handler. On formats: MP3 plays in "All major browsers"; Opus plays in Chrome 33+ and Safari 11+ but "Safari supports Opus in the `<audio>` element only when packaged in a CAF file" and "Ogg containers are not universally supported"; Opus has "the lowest range of latencies of the general-purpose codecs (5 ms to 66.5 ms, compared to at least 100 ms for the others)" ([MDN audio codecs](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs)). Web Audio's `decodeAudioData()` "only works on complete file data, not fragments of audio file data" ([MDN decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)), so chunk-by-chunk playback means either raw PCM scheduled onto `AudioBufferSourceNode`s or a chunked MP3 URL on an `<audio>` element; a whole ~8 s MP3 fetched then decoded is the simplest cross-browser path when the clip is under 100 KB.

## 5. Signals for our design

- **The one-second target is met on paper by every vendor that publishes a number, and the 2.5 s beat hides the whole clip generation for all of them.** The real risk is the vendors that publish nothing (OpenAI TTS, Gemini/Cloud TTS, Polly, PlayHT, MiniMax) — measure before trusting.
- **Text-then-TTS is the only architecture that keeps the JSON verdict on Gemini 3.8 Flash**, keeps the spoken quip identical to the displayed one, and gets faster on cache hits. Native audio-out exists only at OpenAI, at 5× the per-token audio price, with structured outputs undocumented on the audio model.
- **Comedic delivery is a model-tier decision, not a vendor decision**: the fastest tier at each vendor (ElevenLabs Flash, Inworld Flash, Deepgram Aura-2, Rime Mist v3) carries no emotion tags; the expressive tiers (ElevenLabs v3 Conversational ~280 ms, Inworld TTS-2 100 ms P90, Hume Octave 2, Azure HD Omni, Gemini-TTS, Cartesia) are the ones with laughs, sarcasm and whispers — the arithmetic says the slower expressive tiers still fit inside the beat.
- **A ~150-character quip costs $0.002–$0.02 across the board**; price is not a discriminator at couch-game volumes, so licence terms (free tiers are often non-commercial) and per-request minimums matter more than rates.
- **Ship MP3 or WAV/PCM, not Opus-in-Ogg**, if the same bytes must play in Safari and Chrome Android; create or resume the audio context in the submit-tap handler so the verdict can autoplay; cache the audio bytes with the verdict unless a fresh performance per replay is a deliberate design choice.
